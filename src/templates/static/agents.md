# Agent Notes

Static site generated by create-shibumi. Plain committed files in `public/`, no build step, no framework.

## Commands

```sh
bun dev          # preview public/ locally (scripts/preview.ts, dev only)
bun ship:setup   # configure the deploy target (preconfigured: static, public/)
bun ship         # verify public/, build the static image, upload, deploy
```

## Routes and templates

Every file in `public/` is a route. `public/index.html` is `/`, `public/404.html` answers unknown paths. There are no templates or generators; add a generator later by pointing its output directory at `bun ship:setup --static --output-dir <dir> --build-script <script>`.

## Trust boundaries and validation

Before every image build, Ship verifies the output directory from a clean checkout of the committed HEAD: inside the project root, non-empty, `index.html` present, no symlinks. The image contains only that verified output plus a pinned BusyBox httpd running as an unprivileged user; there is no runtime code in production.

## Database

None. Static files only.

## Files Ship generates

`bun ship:setup` writes `Dockerfile`, `compose.yaml`, `.dockerignore`, and `shibumi-server.json` (all committed); static settings live as `dev.shibumistack.static.*` labels in `compose.yaml`. SSH targets stay in `~/.config/shibumi/config.json`, never committed.

## Checks required before commit

`public/index.html` must exist; without a build script, `public/` must be committed or `bun ship` refuses to package it.
